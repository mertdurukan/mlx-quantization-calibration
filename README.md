# The Calibration Cost of the MLX Quantization Ladder

A pre-registered study of how MLX post-training quantization (bf16 → 8/6/5/4/3/2-bit affine,
`mxfp4`, and four mixed-bit recipes) affects **probabilistic calibration** — whether a model's
stated confidence still matches how often it is actually right — as distinct from accuracy,
which the existing MLX/quantization literature already measures. Full design, hypotheses, and
falsification criteria are frozen in [`PREREG.md`](PREREG.md); this file only summarizes what
the pre-registered analysis found.

## Finding

The ladder does not degrade calibration smoothly and uniformly. Across the three eligible main
models (`qwen2.5-1.5b`, `qwen2.5-3b`, `llama3.2-3b`), ECE typically holds close to the bf16
reference through 4-bit and then worsens sharply at 2–3 bits — but the exact shape is
model-dependent, and one model (`qwen2.5-3b`, ARC-Challenge) shows a statistically significant
**non-monotonic** dip at 3-bit (ECE 0.434, 95% CI [0.404, 0.463]) that is *worse* than its own
2-bit cell (ECE 0.254, CI [0.226, 0.281]) — a real reversal in the data, not bootstrap noise,
which falsifies the monotone-degradation hypothesis (H1) as stated. Whether quantization
systematically shifts confidence *toward* wrong answers (H2) also does not hold uniformly:
`llama3.2-3b` confirms the predicted direction in several conditions, `qwen2.5-1.5b` contradicts
it in most of its ARC-Challenge cells. `affine` vs `mxfp4` at matched 4-bit/group-32 (H3) differ
in only one of six model×benchmark cells. See `results/tables/verdicts.json` for the full,
mechanically-computed PASS/FAIL per hypothesis and every contributing cell.

| | bf16 ECE | 2-bit ECE | bf16 accuracy | 2-bit accuracy |
|---|---|---|---|---|
| `qwen2.5-1.5b` / ARC-C | 0.131 [0.111, 0.156] | 0.498 [0.469, 0.527] | 0.765 | 0.244 |
| `qwen2.5-3b` / ARC-C | 0.143 [0.121, 0.164] | 0.254 [0.226, 0.281] | 0.810 | 0.268 |
| `llama3.2-3b` / ARC-C | 0.074 [0.053, 0.096] | 0.517 [0.488, 0.545] | 0.713 | 0.224 |

(Numbers above are illustrative headline cells, not a substitute for the full tables — every
reported number in the actual analysis carries a 95% bootstrap CI over items, per PREREG §4.5.)

## Reproduce

```bash
git clone <this repo>
cd mlx-quantization-calibration
make setup
make reproduce   # runs tests, the full 114-cell grid, then analysis — several hours on an M4 Pro
```

`make reproduce` = `make test` → `python -m src.runner` → `python -m src.analyze`. The grid is
resumable: a cell already written to `results/cells/` is skipped, so an interrupted run can be
restarted with the same command. Requires Apple Silicon (MLX); no CUDA path exists for this
design.

Individual pieces:
- `make verify` — functional smoke test (real convert + load + log-prob read + ECE compute)
- `make pilot` — 1 model × 3 conditions × ARC-Challenge, for a quick sanity check
- `make test` — `pytest tests/`

## What's in the grid

- **5 models**: `qwen2.5-0.5b` (floor control, excluded from main tables), `qwen2.5-1.5b`,
  `qwen2.5-3b`, `llama3.2-3b` (main pool, all bf16-eligible per PREREG §4.2), `llama3.2-1b`
  (measured, did not clear the 50% bf16-accuracy eligibility bar — bf16-only, excluded from the
  quantized grid).
- **14 conditions per eligible model**: bf16 reference, affine 8/6/5/4/3/2-bit @ group 64,
  affine 4-bit @ group 32/128 (matched-group controls), `mxfp4` 4-bit @ group 32, and four mixed
  recipes (`mixed_2_6`, `mixed_3_4`, `mixed_3_6`, `mixed_4_6`).
- **2 benchmarks**: ARC-Challenge and MMLU, 1000 items each, letter-based multiple choice only.
- **114/114 cells `status="ok"`** in the final grid — no failed or dropped cells.

Outputs: `results/tables/table{1,2,3,4}_*.csv` (one per hypothesis), `table5_floor_control.csv`
(the mandatory separate floor-control disclosure, PREREG §4.2 — not a fifth hypothesis table),
`verdicts.json`, and `results/figures/figure{1,2,3}_*.png`. All generated by
`python -m src.analyze` from the per-item parquet files in `results/cells/` — nothing under
`results/` is hand-edited (PROTOKOL Kural 11).

## Scope limits

- Letter-based multiple choice only — no claim about free-generation or verbalized confidence.
- Models ≤ 3B parameters — no claim about 7B+ or frontier-scale behaviour.
- MLX on Apple Silicon (M4 Pro) only — no claim about GPTQ, AWQ, GGUF, or CUDA runtimes.
- Post-hoc recalibration (temperature scaling etc.) is out of scope for this study.
- English-language benchmarks only.

Full scope statement: [`PREREG.md`](PREREG.md) §6. Deviations from the frozen pre-registration,
if any, are logged append-only in [`DEVIATIONS.md`](DEVIATIONS.md).
